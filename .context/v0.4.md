# v0.4

## Catalog page — shared player gate

`Catalog.tsx` switched to `RajaPlayerGate` (the shared gate introduced alongside `Account.tsx` and the strict `/play` guard):

- Removed the page's own duplicated first-time-login block and its standalone `useEnsurePlayer` call.
- Dropped the now-unneeded `isReady` dependency from the data-loading effect.

## Dragon → Soldier/Timer/Messenger/Turret archetype split

`DRAGON` was overloaded — pieces within it had legitimately different trigger semantics (on-kill soldiers, on-turnend timers, on-move messengers, on-activate buildings). Split into function-based archetypes, each with an implied trigger, applied against two house rules: a piece's archetype implies its ability trigger, and `action_cost` must equal its max move distance (buildings keyed to activation-pattern distance instead):

- `DRAGON` renamed `SOLDIER` (`ON KILL`); `TIMER` (`ON TURNEND`), `MESSENGER` (`ON MOVE`), `TURRET` (`ON ACTIVATE`) added.
- All 13 `dragon/` pieces re-triggered/renamed/reclassed to fit (e.g. Ancient Dragon → Ancient Soldier, `ON TURNEND`→`ON KILL`; Dragon Egg → Egg, reclassed `TIMER`; Dragon's Den → Adrenaline Turret, reclassed `TURRET`).
- Ability DSL filters referencing `ARCHETYPE:DRAGON` updated to `ARCHETYPE:SOLDIER` on the pieces that still filter by archetype.
- Catalog folder split: `dragon/` → `soldier/`, `timer/`, `messenger/`, `turret/`, filenames renamed to match (safe — `engine/loader.py` globs recursively and keys by JSON `name`, not path).
- `default_bags/dragon.txt` kept its filename (flavor name, not an archetype label) but its piece-name entries were updated to match the renames.
- Follow-up fix: `frontend/utils/archetypes.ts`'s hand-maintained `ARCHETYPES` mirror wasn't updated in the same pass, causing a `/catalog` runtime crash (`Cannot destructure property 'Icon' of ... undefined`) on any piece carrying a new archetype — fixed, and the update workflow (`card_updater_workflow.md`) revised so the frontend mirror is always touched in the same pass as the backend enum going forward.

## Goblin archetype split (5 of 8 pieces)

Same audit-and-rename workflow run against `goblin/`, reusing the Soldier-rework archetypes rather than inventing goblin-specific ones:

- Exploding Messenger (was Goblin Bomber), Good News Messenger (was Goblin Cheerleader) → `MESSENGER`.
- Messenger King (was Goblin King) → `MESSENGER`, trigger changed to `ON MOVE 5`.
- Dying Timekeeper (was Goblin Knight) → reclassed, and `TIMER` archetype itself renamed `TIMEKEEPER` (enum-wide — also updated `timer/egg.json`, the only other `TIMER` user).
- Stun Turret (was Goblin Pit) → `TURRET`, movement `CROSS 1`→`CROSS 2`, ability duration `TURNS 3`→`TURNS 1`.
- Goblin Warrior, Hobgoblin, Salt Goblin remain `GOBLIN` — not yet walked; `GOBLIN` stays a transitional archetype being migrated out piece by piece.
- `default_bags/goblin.txt` updated to match every rename.

## Berserker/Vanguard split, Messenger → Nomad, unified trigger icons

Resuming the Goblin walk surfaced that `SOLDIER` was overloaded the same way `DRAGON` originally was — all 8 live Soldier pieces are `ON KILL`, leaving nowhere for `ON PROMOTION`-shaped pieces (Goblin Warrior, Hobgoblin) to go. Extended the archetype scheme instead of force-fitting them:

- New `BERSERKER` archetype claims `ON KILL`, absorbing all 8 former Soldier pieces (e.g. Foot Soldier → Mr Berserker, Soldier King → Berserker King). `SOLDIER` itself is retired as a trigger-bearing archetype — redefined as the exception bucket for pieces with no `ability` at all (Night Soldier, Triplet Soldier stay `SOLDIER`, untouched).
- New `VANGUARD` archetype claims `ON PROMOTION` — reserved for the still-open Goblin Warrior/Hobgoblin reclass.
- `MESSENGER` renamed `NOMAD` (pure rename, trigger unchanged) — hit all 4 live Messenger pieces, including the already-shipped Messenger Priest (→ Nomad Priest) from the Soldier rework, not just this session's 3 goblin pieces.
- Archetype icon system unified: since each archetype now implies exactly one trigger condition, the archetype's icon and that trigger's icon are shared (`archetypes.ts` and `abilityTranslatorIcons.ts` no longer choose independently) — `BERSERKER`/`Axe` (also replaces the `ON KILL` trigger, `KILL` effect, and `KILL_COUNT` attribute-chip icons, all formerly `Swords`), `VANGUARD`/`SquareArrowUp`, `NOMAD`/`Footprints`, `TURRET`/`Castle` (trigger icon changed to match the archetype, not the reverse), `SOLDIER`/blank `Square`.
- Catalog reorganized to match: `soldier/` split into `berserker/` (8 pieces) + pruned `soldier/` (2 exceptions); `messenger/` → `nomad/`; `timer/` → `timekeeper/`; `goblin/` pruned to its 3 remaining live-`GOBLIN` pieces. `default_bags/goblin.txt` and `default_bags/dragon.txt` updated to match every rename.
- Open: Berserker's "dark red" and Soldier's "grey" are still placeholder hex values (`#7F1D1D`, `#6B7280`), not yet user-confirmed.

# v0.3

## Piece card redesign

`PieceDetailCard` (shared by `/catalog` and the play room's inspect panel) rebuilt as a compact bordered card:

- No splash art — the `PieceToken` render was dropped entirely.
- 3px orange border, portrait card, sized 5.5cm × 8cm.
- Corners: archetype icon duplicated top-left and bottom-right, action cost top-right, summon cost bottom-left.
- Name centered both horizontally and vertically within the top icon row, uppercase and bold.
- Movement board centered independently of ability text length (previously it drifted upward whenever ability text was present, since both shared one flex stack).

## Ability DSL → human-readable translator

New reusable pieces, not catalog-specific:

- `frontend/utils/abilityTranslator.ts` — pure functions translating the 3-line ability DSL (trigger/effect/target) into full sentences. Covers the entire grammar: all 7 trigger conditions, 5 effect operations, 3 target forms, zones, filters, and patterns.
- `frontend/components/ui/RajaAbilityText.tsx` — thin rendering atom consuming the translator.
- Unrecognized lines fall back to the raw DSL text, styled in red, rather than crashing or going silent.
- Target-line phrasing rewrite: `BAG`/`SHELF` zones read as "From your bag"/"From your hand" (possessive framing) instead of a piece-count sentence; `BOARD` keeps its spatial "on the board within `<pattern>` `<size>`" phrasing. `WHERE` filters render as their own "Where …" line (an embedded newline inside the same field, not a shape change) instead of a trailing parenthetical. Comparators spelled out in full ("less than or equal to", etc.). Count numbers omitted when exactly 1.
- `PUT` effect wording: "Move to your hand" / "Move to your bag" / "Move to the board".

## Raw / Translated / Icons toggle (catalog page)

- Catalog's filter sidebar gained a 3-way `RajaRadio` control switching each card's ability display between raw DSL, translated text, and (new) icons.
- State (`abilityViewMode`) lives in `Catalog.tsx`, threaded down through `CatalogGrid` → `PieceCard`, which branches between `PieceDetailCard` (raw/text) and the new `PieceIconCard` (icons).

## Iconographic ability view

A third, fully icon-based card (`PieceIconCard.tsx`), built so the raw/text views stay byte-for-byte unaffected:

- New `frontend/utils/abilityTranslatorIcons.ts` — mirrors the text translator's grammar coverage, but outputs `{ trigger, effect, target }` chip sequences (icon + optional color + optional label) instead of prose. Falls back to raw red text per-line, same as the text translator.
- Icon/color vocabulary: trigger conditions, effect operations, zones, movement patterns, and role types each got a dedicated lucide icon; `FRIENDLY`/`ENEMY`/`ANY` map to green/red/neutral; numeric attributes compose from concept-icons (e.g. `summon_cost` → summon icon + gem; count-type attributes reuse their trigger's icon alone, no gem).
- Card layout: 4.5cm square. Archetype icon in both top-left and bottom-right corners; action cost (icon above number) top-right; summon cost (number above icon) bottom-left; movement pattern + distance in a flush orange block sandwiched bottom-center between the two bottom corners, mirroring how the name sandwiches the top corners.
- Polish pass: `ALL` counts render as a pill; the `99`/`-99` "practically permanent" magnitude convention renders as an infinity glyph; distinct `WHERE` criteria are joined with "&" (alternatives within one criterion still use "or"); fixed an `action_count` mis-pairing with the cost/gem icon (it's a count, not currency).
- Fixed a live bug surfaced along the way: `PIECE_TYPES` had no entries for `CANNIBAL`/`PACIFIST` despite both being used by real catalog pieces — added on the shared placeholder icon to close the crash risk.
- Warlock's archetype icon changed from `Skull` to `Ghost` (color to light blue) to free `Skull` for exclusive use as the `DEATH` trigger icon.
